# Cyberboss 工具结果外置与并行读取实施计划

## 1. 背景

Cyberboss 的主微信会话需要保留 cc 的人格、关系和对话连续性，不适合为了降低用量而简单拆成无状态执行 Agent。

当前主要浪费来自两类情况：

1. 浏览器快照、Garden 列表等较大工具结果进入会话后，会被后续模型请求重复携带。
2. 多个互不依赖的只读工具被逐个串行调用，每次调用都会触发一次携带完整上下文的模型续跑。

本方案通过“较大结果外置”和“独立读取并行化”降低这部分开销，同时保留 cc 自己浏览、判断和互动的能力。

## 2. 目标

- 小工具结果继续正常进入当前会话。
- 较大结果只向模型返回有判断价值的短工作视图，完整文字暂存在本地。
- cc 需要被省略的文字时，可以按关键词或位置取回。
- 互不依赖的只读操作尽量一次并行执行，减少模型续跑次数。
- Garden 的浏览和互动选择仍由 cc 自己决定。
- 发帖、回复、编辑资料等写操作保持单独、明确、可验证。

## 3. 非目标

- 不拆分独立人格或执行 Agent。
- 不改变日记、时间轴和长期记忆机制。
- 不把 Garden 固化成“检查通知并自动回复”等组合流程。
- 不建设向量检索、XPath/CSS 定位或通用工作流引擎。
- 不尝试从正在运行的 Claude transcript 中删除已有工具结果。

## 4. 总体数据流

```text
cc 调用 Garden / Playwright 工具
              ↓
       本地 MCP 结果处理层
              ↓
     ┌────────┴────────┐
     │                 │
  小结果            较大结果
  原样返回      原文保存到 Result Vault
                         ↓
                短工作视图返回给 cc
                         ↓
                必要时召回部分文字
```

结果处理必须发生在完整结果进入 Claude 会话之前。已经写入 transcript 的历史内容只能在后续 session rollover 时清除。

## 5. 工具结果外置

### 5.1 第一版处理范围

优先处理已确认可能产生大结果的只读工具：

- Playwright：`browser_snapshot`、大型控制台输出、网络请求列表。
- Garden：`list_threads`、`list_games`、`list_activity` 和较长的帖子、评论列表。

点击、导航、填写、短通知、个人资料等小结果保持原样。

写操作的成功状态、实际写入内容、对象 ID、链接和验证结果必须直接留在当前上下文，不进行外置。

### 5.2 初始阈值

阈值做成配置，第一版可使用：

- 不超过 4,000 字符：原样返回。
- 4,000–12,000 字符：保留关键字段和部分文字，其余外置。
- 超过 12,000 字符：保存完整结果，返回短工作视图。

上线观察后再按真实数据调整，不为不同工具预先设计大量特殊规则。

### 5.3 短工作视图

短工作视图不能只有 `artifact_id`，至少包含：

- 调用是否成功。
- 内容是什么、共有多少项。
- 足够判断下一步的标题、作者、时间、ID 或页面主要区域。
- 一小段代表性文字。
- 是否发生截断。
- 原始结果的 `artifact_id`。
- 如何取回被省略文字的简短提示。

示例：

```json
{
  "status": "ok",
  "summary": "获取到 12 篇帖子，当前展示最近 5 篇。",
  "preview": [
    "thread_123｜作者 A｜标题……",
    "thread_124｜作者 B｜标题……"
  ],
  "artifact_id": "garden_20260813_ab12",
  "original_chars": 16840,
  "retained_chars": 2600,
  "truncated": true,
  "hint": "需要被省略的文字时，使用 tool_result_read。"
}
```

第一版采用确定性裁剪，不调用另一个模型生成摘要，避免新增成本和摘要失真。

## 6. 简单文字召回

只增加一个通用工具：`tool_result_read`。

```json
{
  "artifact_id": "garden_20260813_ab12",
  "query": "弥洛",
  "offset": 0,
  "max_chars": 4000
}
```

行为保持简单：

- 提供 `query` 时，执行普通文字搜索，返回命中位置及前后文。
- 不提供 `query` 时，从 `offset` 开始读取一段原文。
- 每次最多返回约 4,000 字符，并返回 `next_offset`。
- 没有命中时明确返回无结果，不自动改写查询或扩大搜索。

防止无效循环：

- 同一轮不重复执行完全相同的读取参数。
- 单个产物每轮默认最多读取三次。
- 连续两次没有获得新文字时停止继续召回。

## 7. Result Vault 与清理

本地存储位置：

```text
~/.cyberboss/tool-results/
```

每条记录只需保存：

- ID、来源工具、创建和过期时间。
- 完整文字结果。
- 原始字符数和必要的调用元数据。

第一版清理策略：

- 文件权限使用 `0600`。
- 浏览器结果默认保留 24 小时。
- Garden 文字默认保留 7 天。
- 服务启动时和固定周期清理过期文件。
- 设置总容量上限，例如 500 MB，超限时优先删除已过期和最旧产物。
- 不保存 Cookie、认证请求头或其他凭据。

第一版不实现引用计数。较宽松的保留时间足以覆盖正常任务，后续只有出现真实误删问题时再增加引用保护。

## 8. 并行读取

### 8.1 优先验证原生并列工具调用

先验证当前 DeepSeek Anthropic 兼容接口能否在一条 assistant 消息中可靠发出多个 `tool_use`：

```text
list_notifications
list_activity
get_self
```

三个调用完成后，结果一起交回模型，只产生一次续跑。

提示规则只需强调：

- 互不依赖的只读查询优先并列调用。
- 后一个调用依赖前一个结果时必须保持串行。
- 写操作不得为了并行而提前执行。

此前抽样的 198 个工具阶段全部是单工具调用，因此必须实测，不能假定仅修改提示词就会生效。

### 8.2 原生并行不可靠时的备用方案

增加一个受限的 `parallel_read` 工具：

```json
{
  "calls": [
    {"tool": "garden.list_notifications", "arguments": {"limit": 10}},
    {"tool": "garden.list_activity", "arguments": {"limit": 10}},
    {"tool": "garden.get_self", "arguments": {}}
  ]
}
```

约束：

- 每批最多 4 个调用。
- 仅允许明确白名单中的只读工具。
- 每项独立返回成功或失败，一项失败不重试整批。
- 每项结果分别经过外置和裁剪。
- 发帖、回复、点赞、资料修改和浏览器点击等写操作不得进入批处理。

这只是减少传输轮次，不替 cc 决定要看什么。

### 8.3 浏览器的并行边界

浏览器的导航、点击、填写和页面变化存在顺序依赖，继续串行执行。只并行读取不会改变页面状态的信息，例如标签列表、控制台错误和已经完成的网络请求摘要。

浏览器降耗主要依赖大 snapshot 外置和后续定向获取文字，并行只作为辅助。

## 9. 实施步骤

### 阶段一：增加基线指标

预计半天。

记录但不保存正文：

- 原始结果字符数和实际返回字符数。
- 每个 turn 的工具调用数。
- 串行阶段数和并行批次数。
- artifact 召回次数。
- 对应会话的输入、缓存输入和输出。

### 阶段二：实现结果外置

预计 2–3 天。

- 实现本地 Result Vault。
- 接入浏览器大型结果和 Garden 大型列表。
- 实现确定性的短工作视图。
- 增加 `tool_result_read`。
- 增加权限、TTL 和容量清理。

### 阶段三：实现并行读取

预计 1–2 天。

- 先做 DeepSeek 原生并列工具调用测试。
- 可靠时只增加提示和回归测试。
- 不可靠时实现受限的 `parallel_read`。
- 验证部分失败不会导致重复执行或整批重试。

### 阶段四：观察和调参

运行 3–7 天，分别观察纯 Garden 浏览、Garden 通知处理、浏览器登录和大型页面读取。根据数据调整截断阈值、每批数量和保留时间。

首个可用版本预计需要 4–7 个有效开发日。

## 10. 验收标准

- cc 仍能自由选择 Garden 浏览和互动路径。
- 大结果被截断时，短视图足以支持下一步判断。
- 被省略文字可通过关键词或分页找回。
- 写操作不会进入并行批处理，也不会隐藏关键执行凭证。
- 过期清理不影响正常 MCP 调用。
- 大型工具结果进入主上下文的字符数减少至少 70%。
- 可并行的三个 Garden 读取从三次模型续跑降低为一次。
- 普通任务很少需要召回，目标为每个产物不超过一次。
- 工具密集任务的模型续跑次数目标降低 20%–40%。
- Garden/浏览器任务累计输入量目标降低 20%–40%。

最后两项是观察目标，不作为预先保证；实际收益以上线后的同类任务对比为准。

## 11. 实施原则

> 大结果暂存在外部，需要文字时简单取回；独立读取尽量一次并行完成；cc 仍然亲自决定去哪里、看什么以及如何互动。
